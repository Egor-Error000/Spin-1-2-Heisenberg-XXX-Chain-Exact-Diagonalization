# XXX--: точная диагонализация спиновой цепочки

Исследуем антиферромагнитную XXX-цепочку со спином $1/2$, $J=1$, при открытых и периодических границах для чётных $N=4,\ldots,26$.

- [Выполненный Jupyter Notebook](notebooks/XXX_chain_ED.ipynb) — формулы, код вызова, таблицы, графики и измерения ресурсов.
- [Подробное теоретическое обоснование](docs/theory.md) — вывод матричных элементов, сектор симметрии, метод Ланцоша, валидация и термодинамический предел.
- [Численный код](src/xxx_chain.py) и [независимый эталон](tests/validate.py).
- [Репозиторий GitHub](https://github.com/Egor-Error000/XXX--).

## Структура

- `src/` — построение разреженного гамильтониана, поиск основного состояния и последовательный/параллельный запуск.
- `tests/` — независимая плотная реализация через матрицы Паули и автоматические проверки.
- `scripts/` — профилирование памяти/CPU и сравнение числа процессов.
- `notebooks/` — итоговый отчёт с сохранёнными выводами.
- `docs/` — математические выкладки.
- `data/` — локальные CSV и PNG, создаваемые notebook. Папка полностью исключена из Git.

Исходные данные уже видны в сохранённых выводах notebook. При повторном запуске файлы `data/results.csv`, `data/energies.png`, `data/resource_measurements.csv` и `data/resource_usage.png` создаются локально; они не отправляются в GitHub.

## Запуск на Windows 11

Запустите Docker Desktop, затем в PowerShell из корня проекта:

```powershell
docker compose up --build -d
docker compose logs notebook
```

Во второй команде показан адрес Jupyter с токеном. Сервер привязан только к `127.0.0.1:8888`. Откройте [notebooks/XXX_chain_ED.ipynb](notebooks/XXX_chain_ED.ipynb) через JupyterLab и выберите **Run All**. Полный пересчёт до $N=26$ занимает несколько минут и достигает примерно 7 ГиБ памяти. Остановить сервер: `docker compose down`.

## Проверка

Сначала запустите независимый эталон и проверки всех рабочих размеров до $N=16$:

```powershell
docker compose run --rm notebook python -m unittest discover -s tests -v
```

Эталон для $N=4,6,8$ строит полный гамильтониан тензорными произведениями матриц Паули и сравнивает элементы и спектры с битовой реализацией. Проверяются все секторы намагниченности при малых $N$, эрмитовость, точное $E_0(4,\mathrm{ПГУ})=-2$, невязки и повторяемость eigsh. Для $N=18,\ldots,26$ notebook сохраняет невязку каждого найденного состояния.

Автоматически пересчитать и сохранить notebook:

```powershell
docker compose run --rm notebook jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=1200 notebooks/XXX_chain_ED.ipynb
```

## Ресурсы и предел $N$

Docker Desktop на проверенном ноутбуке предоставляет 16 логических CPU и 15,34 ГиБ памяти. Отдельный расчёт ПГУ при $N=26$ занял 119 с и достиг пика 6,80 ГиБ, используя примерно одно ядро. Для $N=28$ оценка пика около 28 ГиБ; этот размер не запускался и не поддерживается текущим кодом. Замер одного случая можно повторить:

```powershell
docker compose run --rm -T notebook python scripts/profile_resources.py 26 PBC
```

`scripts/benchmark.py` сравнивает от 1 до 14 процессов на малой сетке $N\leq16$. Для неё один процесс был быстрее; при полном расчёте последовательный режим также предотвращает наложение пиков памяти крупных размеров.
