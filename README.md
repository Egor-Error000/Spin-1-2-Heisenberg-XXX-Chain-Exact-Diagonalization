# XXX-цепочка: точная диагонализация

Проект вычисляет энергию основного состояния спиновой цепочки Гейзенберга
для чётных `N=4,…,16` с открытыми (ОГУ) и периодическими (ПГУ) границами.
Итоговый [notebook](XXX_chain_ED.ipynb) уже выполнен: в нём есть формулы,
таблица чисел и график. Числа также сохранены в [CSV](results.csv), график —
в [PNG](energies.png).
Дополнительный раздел notebook показывает измеренные время, CPU и память
для `N=16,…,26`. Исходные замеры — в [CSV](resource_measurements.csv),
график — в [PNG](resource_usage.png).

## Запуск на Windows 11

1. Запустите Docker Desktop.
2. Откройте PowerShell в этой папке и выполните `docker compose up --build`.
3. Возьмите адрес Jupyter с токеном из вывода Compose и откройте его в браузере.
   Если Compose запущен в фоне, адрес показывает `docker compose logs notebook`.
4. В JupyterLab откройте `XXX_chain_ED.ipynb`. Сервер доступен только с этого
   компьютера по `http://localhost:8888`.

Остановить сервер: `Ctrl+C` при запуске в терминале или `docker compose down`
при запуске в фоне.

## Проверка и повторный расчёт

Перед пересчётом выполните независимую проверку:

```powershell
docker compose run --rm notebook python validate.py
```

Она сравнивает построение битовыми операциями с независимым гамильтонианом
из матриц Паули при `N<=8`, проверяет все секторы намагниченности для малых
цепочек, точное `E0(4, ПГУ)=-2`, эрмитовость, невязки и повторяемость `eigsh`
для всех рабочих размеров.

Затем откройте notebook и выполните **Run All**. Повторное выполнение
перезапишет `results.csv` и `energies.png`. Для автоматического выполнения:

```powershell
docker compose run --rm notebook jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=600 XXX_chain_ED.ipynb
```

`benchmark.py` сравнивает 1, 2, 4, 8 и 14 процессов. На проверенном ноутбуке
для указанной небольшой сетки быстрее оказался 1 процесс (0,42 с против
1,60–2,25 с), поэтому он выбран в notebook. Число процессов можно изменить
в ячейке `WORKERS` до 14; в контейнере каждый использует один поток BLAS и
Numba, чтобы избежать перегрузки процессора.

## Ресурсы и предельный размер

Профиль отдельного расчёта можно повторить командой:

```powershell
docker compose run --rm -T notebook python profile_resources.py 26 PBC
```

Профайлер разогревает Numba, затем измеряет построение матрицы и `eigsh`.
Текущий Docker Desktop предоставляет 16 логических CPU и 15,34 ГиБ памяти.
Проверенный `N=26` (ПГУ) использовал пик 6,80 ГиБ и 119 с; загрузка
составила около 91% одного ядра. Для `N=28` оценка пика около 28 ГиБ,
что превышает доступную память Docker. Поэтому при текущем алгоритме и
настройках практический максимум — `N=26`; `N=28` не запускался.

## Git

Проект хранится в локальном Git-репозитории. `results.csv`, оба PNG и
выполненный notebook включены в историю; `.cache`, Python-кэш и временные
файлы Jupyter исключены. Удалённый репозиторий не настроен.

Численный код находится в `xxx_chain.py`; `validate.py` содержит независимый
эталон. Вычислительное ядро использует NumPy, Numba и SciPy; Matplotlib строит
график, `tqdm.auto` отображает ход длительных этапов.
