# Последний отчёт: полная матрица против центрального сектора

Замер сравнивает две реализации одной и той же задачи для OBC и PBC: полную матрицу Гамильтониана размерности $2^N$ с вычислением всего спектра через плотную диагонализацию и разреженную матрицу центрального сектора с поиском только минимального собственного значения. Каждый вариант запускается в отдельном процессе; учитываются построение, решение и пиковая память RSS. Верификация сравнивает энергии основного состояния.

Для всех 24 пар (N=3,...,14, две граничные конфигурации) расхождение энергий не превысило $1.07\times10^{-14}$. При N=14:

- OBC: плотный расчёт занял 548.36 с и достиг 7.12 ГиБ пикового RSS; разрежённый занял 0.00444 с и достиг 0.150 ГиБ. Отношение времени — около 123 000.
- PBC: плотный расчёт занял 558.77 с и достиг 6.40 ГиБ; разрежённый занял 0.00431 с и достиг 0.150 ГиБ. Отношение времени — около 130 000.

Для обеих границ получено $E_0=-6.02672466186217$ (OBC) и $E_0=-6.26354953354704$ (PBC) в обоих методах с указанной выше точностью. Плотный эксперимент остановлен на N=14: прогноз для следующего размера N=15 составляет около 40.5 ГиБ и превышает лимит задания замера около 15.70 ГиБ. Это ограничение относится к бюджету конкретного контейнерного замера, а не к объёму свободной RAM на компьютере.

Пользователь указал, что на хосте сейчас доступно около 22 ГБ. При проверке Docker Engine 5 октября 2026 г. его `MemTotal` составлял 23.47 ГиБ. Эти величины описывают разные уровни памяти и могут меняться; диспетчер заново читает лимит Docker при каждом запуске, берёт 70% и учитывает резерв 0.5 ГиБ на каждый рабочий контейнер.
